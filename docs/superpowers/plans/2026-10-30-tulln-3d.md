# Tulln 3D flood Implementation Plan

Use subagent-driven-development. Approved conversational spec: realistic high bird-eye 3D Tulln-inspired landscape; free mouse-drawn sandbag barriers; click houses to rescue; no teams; six minutes with 45-second gentle start; pause freezes simulation but allows queued barrier planning; limited reusable sandbags; forgiving challenge. Current desktop Chrome and Safari compatibility targets, test ONLY Chrome on headless Ubuntu; never claim Safari or hardware GPU acceptance from software rendering.

## Global Constraints
TypeScript/Vite/Bun. Babylon.js WebGPU GPU rendering, no legacy browser requirement. 256x192 height/water grid, conserved volume and positive depths. 360-second reproducible flood. Six-second parallel rescues. Shared terrain/building/barrier coordinates. Worker water core. Benchmark TS first; if p95 >4ms/step compare Rust/Wasm, adopt only >=20% faster with equivalence tests. Chrome evidence records adapter, CPU/GPU limits and actual tests. No push, publication or Safari installation.

## Task 1: Grid simulation and gameplay core
Create src/flood/{types,terrain,simulation,game}.ts and tests/flood.test.ts; leave existing V3 core temporarily for integration. Export explicit typed interfaces for terrain dimensions/heights/buildings/gates; snapshots with water depths, barriers, rescues, resources, phase/time/results; create/step/command functions; commands for drawn barriers/remove/rescue/gates/pause/resume/reset. Deterministic 256x192 terrain inspired by Tulln: curved broad river, low waterfront, streets, houses and fields; playable local scene, not real hazard model. Finite-volume conservative head-driven neighbor flux with bounded donor outflow and accounting. Barrier edges raise sill, not water floor; staged construction, overtopping, obstacle collisions, overlap cost dedup, removal refunds, deep-water rejection. Paused queued lines reserve resources, revalidate on resume. Parallel six-second house rescues idempotent, depth/duration damage. Fixed flood mild first45sec, duration360. Write meaningful tests first; benchmark core; report public interfaces precisely for next task. Commit and self-review.

## Task 2: WebGPU 3D landscape
Create src/scene/ with Babylon WebGPU async initialization, renderer and input picking, using Task1 terrain/snapshots as truth. Install @babylonjs/core pinned via Bun lock. Natural detailed Austrian roofs, trees, gardens, fields, roads, embankments; curved Danube; shadows and depth; high angled fixed-orientation camera with zoom/pan/reset. Detailed continuous water mesh driven by actual depths with dry cells invisible, animated current and shore/depth variation. No fake flood overlay disconnected from core. Public scene API initialize(canvas), update(snapshot), dispose, on world-position pointer interactions and house/gate picks. Tool preview visible with valid/invalid colors. Quality tiers and adapter diagnostics. No full UI yet; build and unit checks. Report interface, commit/self-review.

## Task 3: Interaction, worker and integrated round
Replace src/main.ts/style.css with map-first polished screen and small toolbar, remove old V3 renderer/core/tests/tools if unused. Integrate worker protocol (init,command,advance/test, snapshot,diagnostics); bounded fixed steps no huge catchup. Canvas drawing free lines preview/cost; escape/cancel; remove/refund; click house/gate; camera pan via right drag and zoom, overview button. 360-sec round,45sec intro,6sec parallel rescue. Pause queued barriers, auto pause on hidden, restart/result. HUD time/material/safe/damage, contextual warnings; no sidebar dashboard/team controls/three preparations. Robust GPU init errors/retry, worker errors and device loss. Test API only ?test=1 for deterministic browser checks and world projection. Core step benchmark p95 and report Wasm trigger decision; no benchmark claims from synthetic guesses. Update build config and focused meaningful input/game tests. Commit/self-review.

## Task 4: Chrome acceptance and documentation
Replace browser tests for current game: actual canvas drag barrier, invalid/canceled drawing, overlapping cost, remove refund, house click/parallel idempotent rescue, gate, camera picking, pause/queue/resume, reset, complete360s accelerated and full real-time round. Build production then exclusive4187 preview. Use actual available Chrome with headless WebGPU adapter detection; software adapter is allowed for functional testing but not GPU performance acceptance. Capture1440x960 initial/crest/end screenshots and diagnostics. Compare no-action/barrier/gate strategies same flood and prove water/damage differences. README/status replace V3 instructions; record hardware unavailable and Safari untested honestly. Test core/build/browser. No Safari install. Commit/self-review.

## Review Focus
Conservation and dry-cell stability; actual rendered flood matches grid; world picking after camera changes; queue resource accounting; GPU/software and Safari evidence honesty. Fresh task reviewer per task, then broad whole-branch review and single combined fix wave. Work remains local.
